## 标准开发流程

### 1. 修改代码
- 直接在 Android Studio / Trae 中修改源文件
- 遵循现有代码风格（Compose + Miuix 组件库）

### 2. 编译 Debug 包
```powershell

cd D:\new tvbox
.\gradlew.bat :app:assembleDebug --console=plain -q
```

### 3. 安装到设备（ADB 直装）
```powershell
$adb = "C:\Users\15791\AppData\Local\Android\Sdk\platform-tools\adb.exe"

```
- 成功输出 `Success`；设备未授权时先执行 `adb devices` 确认状态
- 遇 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（签名不一致）先 `adb uninstall com.ican.tvplay` 再安装

### 4. 启动验收
```powershell

```
- 按需求逐项验证功能是否正常

### 5. Git 提交
```powershell

git commit -m "类型: 简要描述"
```

### 6. 推送到 GitHub

- **PAT 禁止写入 `.git/config`、禁止写进任何文档或提交**

## 调试与诊断规范

- 排查用日志必须用 `BuildConfig.DEBUG` 守卫（参考播放器的 `PipTrace`），release 包不允许输出诊断日志。
- 统一用同一个 TAG 输出，方便过滤：
```powershell
& $adb logcat -s PipTrace
```
- 排查结束后删除临时日志、截图、UI dump，不留在工作区（见「仓库清洁规范」）。
- 涉及播放器/画中画等系统行为时，优先用录屏逐帧 + `adb shell dumpsys` 取证，避免凭猜测改代码。

## 发布流程

### 版本号
- 在 `app/build.gradle.kts` 递增 `versionCode` / `versionName`，创建 release 前确认已更新。

### 签名
- 签名文件：`app/release.keystore`（本地文件，已被 `.gitignore` 忽略，**禁止提交**）。
- 签名凭据（`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD`）存放在根目录 `local.properties`，由 `app/build.gradle.kts` 的 `signingConfigs.release` 读取。
- **禁止把密码硬编码进构建脚本或提交到仓库**；换机器时需在本地 `local.properties` 补齐这三项，否则 release 打包失败。

### 打包
```powershell
$env:JAVA_HOME="C:\Users\15791\.gradle\jdks\jetbrains_s_r_o_-21-amd64-windows.2"
.\gradlew.bat :app:assembleRelease --console=plain
```
- 输出：`app/build/outputs/apk/release/app-release.apk`
- release 开启 `isMinifyEnabled + isShrinkResources`；新增反射调用、JS 接口需同步补充 `proguard-rules.pro`，否则会被裁剪。

## 仓库清洁规范（防误提交）

### 1. 禁止入库的内容

| 类型 | 示例 | 处理方式 |
|------|------|----------|
| 编译产物 | `*.apk`、`build/`、`.gradle/`、`.kotlin/` | 本地保留，由 `.gitignore` 忽略 |
| 调试截图/录屏 | 根目录 `screen*.png`、`*.mp4` | 检查完立即删除 |
| UI 层级 dump | `ui.xml`、`.ui_dump*.xml` | 排查完立即删除 |
| 图标设计稿 | 根目录 `icon_*.jpg/png` | 选定后删除，只保留 `res/` 内正式图标 |
| 第三方库解压产物 | `app/libs/*-extract/`、`*.zip`、临时 `classes.jar` | 只保留构建实际引用的 `*.aar` |
| 签名/密钥 | `*.jks`、`*.keystore` | 必须保持忽略，禁止提交 |

判定依据：仓库只放**源码 + 构建必需文件**。能被重新生成、只是本机排查用的，一律不入库。

### 2. .gitignore 基线

现有规则覆盖：`*.apk`、`build/`、`.gradle/`、`.kotlin/`、`local.properties`、`.idea/`、`*.jks`、`*.keystore`、`*.log`，以及根目录调试垃圾：
```
/ui.xml
/.ui_dump*.xml
/screen*.png
/icon_*.*
apk_check_tmp/
```
新增一类临时文件时，**同一次提交内**同步补充忽略规则。

### 3. 提交前自检

```powershell
git status --short          # 确认只包含预期的改动
git ls-tree -r -l HEAD      # 检查是否有意外的大文件
```
重点核对根目录和各 `libs/` 目录，发现 APK、截图、解压产物立即移除后再提交。

### 4. 已被跟踪的垃圾怎么删

`.gitignore` **只对未跟踪文件生效**。若垃圾已被 Git 跟踪，必须显式移除：
```powershell
git rm -r -- <路径>          # 同时删除本地文件
```
只加忽略规则而不 `git rm`，下次仍会被推送。

删除 `app/libs/` 下的非 AAR 文件后，必须重新编译验证（`.\gradlew.bat assembleDebug --console=plain`），确认 `fileTree("libs") { include("*.aar") }` 依赖不受影响。

### 5. 误提交后的处置

- **常规清理**：新增一次删除提交并推送，历史保留（推荐，无风险）。
- **彻底瘦身**：`git filter-repo` 重写历史 + 强制推送，属不可逆操作，必须先确认后再执行。

## 注意事项
- 修改 UI 后必须重新编译 + 安装（`adb install -r`）才能看到效果
- 不要直接在手机上覆盖安装有签名冲突的包（先卸载再装）
- commit 信息要简明扼要，说明做了什么改动
- 提交前确保编译通过；纯文档改动可跳过编译
