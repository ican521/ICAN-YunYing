## 仓库清洁规范（防误提交）

### 1. 禁止入库的内容

| 类型 | 示例 | 处理方式 |
|------|------|----------|
| 编译产物 | `*.apk`、`build/`、`.gradle/`、`.kotlin/` | 本地保留，由 `.gitignore` 忽略 |
| 调试截图/录屏 | 根目录 `screen*.png`、`*.mp4` | 检查完立即删除 |
| UI 层级 dump | `ui.xml`、`.ui_dump*.xml` | 排查完立即删除 |
| 图标设计稿 | 根目录 `icon_*.jpg/png` | 选定后删除，只保留 `res/` 内正式图标 |
| 第三方库解压产物 | `app/libs/*-extract/`、`*.zip`、临时 `classes.jar` | 只保留构建实际引用的 `*.aar` |
| 签名/密钥 | `*.jks`、`*.keystore` | 必须保持忽略，禁止提交 |

判定依据：仓库只放**源码 + 构建必需文件**。能被重新生成、只是本机排查用的，一律不入库。

### 2. .gitignore 基线

现有规则覆盖：`*.apk`、`build/`、`.gradle/`、`.kotlin/`、`local.properties`、`.idea/`、`*.jks`、`*.keystore`、`*.log`，以及根目录调试垃圾：
```
/ui.xml
/.ui_dump*.xml
/screen*.png
/icon_*.*
apk_check_tmp/
```
新增一类临时文件时，**同一次提交内**同步补充忽略规则。

### 3. 提交前自检

```powershell
git status --short          # 确认只包含预期的改动
git ls-tree -r -l HEAD      # 检查是否有意外的大文件
```
重点核对根目录和各 `libs/` 目录，发现 APK、截图、解压产物立即移除后再提交。

### 4. 已被跟踪的垃圾怎么删

`.gitignore` **只对未跟踪文件生效**。若垃圾已被 Git 跟踪，必须显式移除：
```powershell
git rm -r -- <路径>          # 同时删除本地文件
```
只加忽略规则而不 `git rm`，下次仍会被推送。

删除 `app/libs/` 下的非 AAR 文件后，必须重新编译验证（`.\gradlew.bat assembleDebug --console=plain`），确认 `fileTree("libs") { include("*.aar") }` 依赖不受影响。

### 5. 误提交后的处置

- **常规清理**：新增一次删除提交并推送，历史保留（推荐，无风险）。
- **彻底瘦身**：`git filter-repo` 重写历史 + 强制推送，属不可逆操作，必须先确认后再执行。

## 注意事项
- 修改 UI 后必须重新编译 + 推送 + 安装才能看到效果
- 不要直接在手机上覆盖安装有签名冲突的包
- commit 信息要简明扼要，说明做了什么改动
