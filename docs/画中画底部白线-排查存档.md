# 画中画底部白线 —— 问题排查存档

- **状态**：已关闭（判定为系统级问题，App 无法修复）
- **设备**：红米 K Pad 2（HyperOS / 26048RP6AC），ADB `VKIZX4JNAQ9DRCCM`
- **工程**：ICAN 影视（`D:\new tvbox`，Compose + PlayerView surface_view）

## 一、最终结论

画中画小窗底部（以及静态时四个圆角）的白色细线，是 **HyperOS 画中画窗口自身的系统圆角描边**，由系统合成器绘制在窗口边界上，**不是应用内容，也不是透出桌面/窗口表面**。任何 PiP 应用在 HyperOS 上都会带它，**App 代码无法消除**。实测 fongmi（独立实现的成熟播放器）同样有此线，为同一来源。

## 二、证据链

| # | 证据 | 说明 |
|---|------|------|
| 1 | 窗口背景设成不透明纯黑后，白线仍是白色 | 不是透出窗口表面/浅色背景/桌面；应用内容盖不到它 |
| 2 | 两个独立实现（本 App 与 fongmi）都有同一条线 | 不是应用代码，共同点只剩系统 PiP 机制 |
| 3 | 静态时四个圆角各有一点小白线 | 正是系统圆角窗口描边的典型形状 |
| 4 | 放大过渡时底部成一条更明显的白线 | 缩放过程中窗口重合成，描边被放大感知 |
| 5 | 白线只在窗口最底部/四角，不在视频画面内 | 指向窗口边框，而非视频内容/叠加 UI |

## 三、排查过程（多轮假设 → 验证 → 结论）

1. **假设**：固定 `delay(900)` 掐系统放大动画，超时后根底色提前翻回浅色 → 底部露白。
   **处理**：改为轮询 decorView 尺寸收敛（`waitForPipExpansion`）。**无效**。
2. **假设**：AppRoot 根底色浅色。**处理**：根底色随 `videoPresent` 转黑。**无效**。
3. **假设**：HyperOS 画中画窗口透明表面，内容未铺满底部缝隙透桌面。**处理**：`decorView.setBackgroundColor(黑)`。**无效**。
4. **假设**：窗口表面透明由 window 背景决定。**处理**：`window.setBackgroundDrawable(不透明黑)`。**无效（白线仍白）**。
5. **结论**：PipTrace 日志确认放大期间分支 `pipHold/full`、仅渲染纯黑视频、无叠加 UI、无白描边分支；结合 fongmi 同款 + 四角圆角描边 → 判定为**系统 PiP 窗口圆角描边**。
